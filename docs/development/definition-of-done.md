# Definition of Done

A change is done only when all applicable items are satisfied.

## Behavior
- Requested behavior matches requirements and Accepted Product Decisions.
- Edge cases and authorization implications have been considered.

## Architecture
- Implementation matches Accepted ADRs.
- No new significant architecture choice was introduced without approval.
- New dependencies have explicit rationale.

## Verification
- Appropriate automated tests exist.
- Formatters and linters pass.
- Type checks/static analysis pass where configured.
- Unit/integration/end-to-end tests pass as applicable.

## Documentation
- Requirements remain accurate.
- Relevant Decision Records are linked or updated.
- Architecture/API/developer documentation is synchronized.

## Traceability
The completion report names:
- requirement IDs addressed
- Decision Records relied upon
- validation commands executed
- known limitations or follow-ups
